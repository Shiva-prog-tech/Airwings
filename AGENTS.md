# AGENTS.md — Airwing Technologies website

Rules for anyone (human or AI agent) working in this repo. Read this before writing code.
If a rule here conflicts with a habit, the rule wins. If a rule is wrong, fix this file in the same change.

- **Project:** single-page marketing site for **Airwing Technologies**, a precision aerospace and defence CNC machining company in Peenya, Bengaluru (ISO 9001:2015, MSME, est. 2022).
- **Goal:** an "unreal" scroll-driven landing page that still loads fast, reads well on phones, and never invents facts.
- **Content source of truth:** [`docs/info.md`](docs/info.md). **Design and section plan:** [`docs/REVAMP_PLAN.md`](docs/REVAMP_PLAN.md).

### Placement rules
- **One component per folder** under `components/*/`: `name.tsx` + `name.module.scss`, plus sub-components or a hook if needed. Re-exports via `index.ts` are **not** used; import the file directly.
- A section that needs a phone stand-in keeps it in the same folder (`projects/projects-mobile.tsx`).
- Code used by **2+ sections** moves to `components/ui/` (visual) or `lib/` (logic). Never import one section from another.
- New copy goes in `content/`. New image: add the original to `assets/images/`, an entry in `sources.json`, run `pnpm images`.

## 4. Naming and code style

- **Files and folders:** `kebab-case` (`stat-counter.tsx`, `use-pin.ts`). **Components:** `PascalCase` named exports (`export function StatCounter`). No default exports except where Next requires them (`page.tsx`, `layout.tsx`, `sitemap.ts`…).
- **CSS Module classes:** `camelCase` (`styles.specRow`). State goes in `data-*` attributes (`data-active`, `data-state="open"`), not extra classes.
- **Types:** `type` over `interface` unless extending. Data types live next to their data in `content/*.ts` and are exported (`export type Machine = …`).
- Use `as const` for static data, and `satisfies` to type-check it without widening.
- Comments explain **why**, not what. Keep them short. Delete commented-out code.
- Imports, in order: react/next → third-party → `@/lib` → `@/content` → `@/components` → relative → styles. Use the `@/` alias for anything outside the current folder.
- Formatting: 2 spaces, double quotes, no semicolons, trailing commas. Match the surrounding code.

## 5. React and Next.js practices

- **Server Components by default.** Add `"use client"` only for state, effects, refs used by GSAP, or browser APIs. Push it to the smallest leaf (e.g. a server section that renders a client `<Marquee>`).
- Never read `window`, `document`, `Date.now()` or `Math.random()` during render or at module top level. Do it in effects.
- Pass **serialisable props** (plain data) from server to client components. Pass content keys, not JSX blobs, where possible.
- Keys come from stable ids (`machine.id`), never array indexes, for lists that can change.
- Forms use **Server Actions** + `useActionState`. Validate on the server with zod, always. Client hints (required, type=email) are UX only.
- Metadata goes through the `metadata` export in `app/layout.tsx`/`page.tsx`. JSON-LD (Organization + LocalBusiness) is built in `lib/seo.ts`.
- No `"use client"` in `app/page.tsx` or `app/layout.tsx`.

## 6. Styling rules (SCSS)

- **Tokens only.** Colours, font families, type scale, spacing, radii, z-index and easing come from `styles/abstracts/_tokens.scss` (exposed as CSS custom properties on `:root`). **No raw hex values or magic px in component files.** A missing token goes into `_tokens.scss` first.
- Every module starts with `@use "abstracts" as *;` (the `styles/` load path is set in `next.config.ts`). Abstracts output **no CSS**, so `@use` them anywhere.
- **Mobile-first.** Base styles target phones; enlarge with `@include up(md)` / `up(lg)` / `up(xl)` from `_breakpoints.scss`. No `max-width` queries except to opt out of a desktop-only effect.
- Layout uses **CSS Grid / Flexbox** and the `.container` from `base/_layout.scss`. No grid frameworks.
- Fluid type and spacing use `clamp()` tokens (`--fs-display`, `--space-section`).
- Nesting max 3 levels. No `!important` (the only exception is honouring `prefers-reduced-motion`).
- Animate only `transform`, `opacity`, `clip-path`, `filter` (sparingly). Never animate `width`, `height`, `top` or `left`.
- `backdrop-filter` is allowed only on small elements (pills, header), never full-screen.
- One theme: **light-first** aluminium canvas with graphite bands for rhythm. Keep contrast AA (4.5:1 body, 3:1 large text).

### Design language ("Shop floor", Parody "Digital Agency" layout)
- **Palette** (from what is physically in Airwing's photos):
  - Aluminium `$canvas #E8EAED` page and `$canvas-raised` cards. Light-first.
  - Graphite `$ink #16181C` text, and `$graphite` dark bands (infrastructure, projects, footer, preloader).
  - Steel `$steel` / `$steel-dark` for secondary text and hairlines.
  - Logo indigo `$indigo #2E3192` **only** for big brand moments: menu layer, mega-panel card, monograms.
  - Signal `$signal #E4572E` (BFW machine-door red-orange) **only** for CTAs and key tolerances.
  - Logo green `$ok` for the tiny "certified" check only.
- **Type:**
  - Bebas Neue, uppercase, for display.
  - Inter for body.
  - **IBM Plex Mono for every measured value** (`0.02 mm`, `Al 7075-T6`, `3100 × 1700 × 1000`).
- **Layout vocabulary** (Parody Home 5 + Full Screen Slicer):
  - Poster-scale headlines with an inline image pill.
  - Round CTA buttons.
  - Full-bleed parallax photos.
  - Numbered service rows that reveal a thumbnail.
  - Giant scrubbed type bands.
  - Award-style hairline rows (instruments).
  - Full-screen pinned project slicer.
  - Infinite two-row banner before the footer.
- **Avoid template tells:**
  - No ALL-CAPS eyebrow label above every heading.
  - No single highlighted word inside a headline.
  - No `01 / 02` numbering unless the content is a real sequence (services, process steps, slides).
  - No `→` appended to every button.
  - No navy + single neon accent.

## 7. Motion rules (GSAP)

- Import GSAP **only** from `@/lib/motion/gsap`. Never `import gsap from "gsap"` in a component. Plugins are registered once, in the browser only.
- Every animation lives in `useGSAP(() => { … }, { scope: ref })`. Select elements **inside the scope** (refs or `data-*` hooks). Never use global class selectors.
- **Never** call `ScrollTrigger.getAll().forEach(t => t.kill())`. Clean up through the `useGSAP` context or `mm.revert()`.
- Pinned or heavy scenes run inside `gsap.matchMedia(DESKTOP_MEDIA)`. Phones get a simpler, non-pinned stand-in rendered from the same content.
- **Reduced motion:** guard every effect with `prefersReducedMotion()`. The page must be complete and readable with motion off: final states visible, no pins, marquees static.
- **ScrollSmoother is on.** `<SmoothScroll>` renders first inside `#smooth-content`, so it exists before any ScrollTrigger. Fixed UI (header, menu, preloader, scroll ring) sits **outside** `#smooth-wrapper`.
- **Never use CSS `position: sticky`**, because it can't work inside the smoother's transformed content. Use `usePin` (one element) or `useStack` (stacking panels).
- In-page anchors use `<AnchorLink>` / `scrollToHash()`, which go through `smoother.scrollTo` with a native fallback. The menu pauses the smoother while open.
- Don't use ScrollTrigger `snap` inside the smoother (it jumped the page to the top in testing).
- SplitText effects wait for `document.fonts.ready`. Call `ScrollTrigger.refresh()` after layout-changing loads.
- Prefer the **markup-driven effects** in `lib/motion/effects.ts` over one-off code:
  - `data-reveal="up|down|left|right|fade"` (+ `data-reveal-delay`)
  - `data-reveal-group` (stagger children)
  - `data-mask` (clip-path image wipe)
  - `data-text-fill` (scroll-scrubbed line fill)
  - `data-title` (3D line rise)
  - `data-speed` / `data-lag` (parallax via ScrollSmoother `effects`)
- Content is visible without JS. Hidden pre-animation states apply only under `html.has-motion`, set by the inline bootstrap script, with a 3 s fail-safe.
- Budget: at most **one pinned scene on screen at a time**. Total pinned scroll on the page ≤ ~6 viewport heights.

## 8. Content and accuracy

- Every fact on the page must come from `docs/info.md`. **Don't invent** numbers, certifications, customers, testimonials or team photos.
- Unconfirmed claims stay out until the client confirms them: **AS9100D**, the 6000 × 2500 × 800 mm capacity, and the Skyroot / L&T logo permission. Track them in `docs/info.md`.
- Use the correct spellings: **Hindustan** Aeronautics, LCA **Tejas**, **MANN+HUMMEL**.
- Phone numbers render as `tel:` links and email as `mailto:`. The address is a semantic `<address>`.

## 9. Performance, accessibility and SEO budgets

- **Lighthouse (mobile, production build):** Performance ≥ 90, Accessibility 100, Best Practices 100, SEO 100. CLS < 0.05.
- **JS:** home page ≤ ~250 KB gzipped (React/Next ≈ 160, GSAP ≈ 66). Check with `pnpm build` output.
- **Images:**
  - Always use `<SiteImage>` with a correct `sizes`.
  - Only the hero's first slide is `priority`.
  - Every image has a meaningful `alt`, or `decorative` if it adds nothing.
- **Accessibility:**
  - One `<h1>`, then sequential headings.
  - Landmarks: `header`, `nav`, `main`, `footer`.
  - Skip link to `#main`.
  - Visible `:focus-visible` styles on every interactive element.
  - Menus close on Escape and trap focus with `inert`.
  - Decorative marquees are `aria-hidden`.
  - Tables are real `<table>` with `<caption>` and `scope`.
- **SEO:**
  - Title and description in metadata, plus OG image.
  - JSON-LD `Organization` + `LocalBusiness` with name, address, phones and email.
  - `sitemap.ts` and `robots.ts`.

## 10. Security

- The RFQ Server Action:
  - Validates with zod.
  - Rejects the honeypot.
  - Caps field lengths, and file uploads by type (PDF, STEP, STP, DWG, DXF, images) and size (≤ 4 MB, because Vercel caps request bodies at 4.5 MB).
  - Never echoes raw input into HTML.
- Secrets (email API keys) live in env vars only (`.env.local`, Vercel env). `.env*` is git-ignored; document required vars in `.env.example`.
- External links get `rel="noopener noreferrer"`. The map is an `<iframe>` with `loading="lazy"` and `referrerpolicy="no-referrer-when-downgrade"`.

## 13. Definition of done

1. `pnpm typecheck`, `pnpm lint` and `pnpm build` pass with no new warnings.
2. Checked in a browser (`run` / `claude-in-chrome`):
   - Widths 375, 768 and 1440 px.
   - Reduced motion on and off.
   - Keyboard-only navigation.
   - No console errors.
3. Copy matches `docs/info.md`. No placeholder text or lorem.
4. `simplify` and `code-review` were run on the diff, and findings were fixed or consciously skipped.
5. Any new rule or structure change is reflected in this file.
